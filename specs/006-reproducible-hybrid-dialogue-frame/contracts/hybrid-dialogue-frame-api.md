# Contract: Hybrid dialogue frame API behavior

## Selected-frame hybrid generation

- `POST /api/visual/frames/:frameId/generate` orchestrates hybrid generation for one selected split dialogue frame.
- Ordinary dialogue panels MUST follow the hybrid model:
  1. ensure scene background (reuse ready or create/retry failed);
  2. ensure one character visual state per required panel;
  3. assemble through the shared renderer.
- The endpoint MUST NOT satisfy ordinary dialogue success by silently returning two independent full-scene panel images as the hybrid result.
- Response includes updated visual payload plus frame-level operation summary:
  - `hybridPhase`: `background` \| `character-states` \| `assembly` \| `complete` \| `failed`
  - `generationFailures`: component-scoped safe failures
- Partial success is allowed. `visualReady` is true only when background and all required character states are ready.

## Component status surface (GET `/api/visual`)

Each split frame includes enough fields for honest UI:

- `visualReady`
- `hybrid.background`: `{ status, assetId?, errorKind? }`
- `hybrid.panels[i]`: `{ subject, status, assetId?, errorKind?, zoom, positionX, positionY }`
- `hybrid.compositionMode`
- concise panel descriptions / detailed briefs distinct from compiled prompts
- visible frame number remains a UI concern outside the canvas; API continues to expose stable `frame.id`

Fitted/overflow display pieces MUST preserve hybrid assignment fields exactly as feature 005 preserved panel visual fields.

## Character-state / panel regenerate

- `POST /api/visual/frames/:frameId/panels/:panelIndex/generate` regenerates one character state for hybrid ordinary dialogue panels.
- First-generation reference policy:
  1. approved identity anchor;
  2. project style seed when distinct.
- Performance references and previous-result revision authority are out of scope for feature 006 first-generation path; if later reused, they must not replace identity authority.
- A ready scene background for the same version/scene MUST be reused rather than regenerated by character-state retry.
- Failed background during a frame generate may be retried by frame generate; no dedicated background-edit endpoint is required in 006.

## Placement

- `PATCH /api/visual/frames/:frameId/panels/:panelIndex/placement` updates character zoom/pan/fit only.
- MUST NOT call the image provider.
- MUST NOT mutate or regenerate the scene background.
- Placement survives reload for the same storyboard version.

## Diagnostic export

- Explicit export endpoint, e.g. `POST /api/visual/frames/:frameId/diagnostics/export` or `GET` with same scope.
- Returns a local archive (`application/zip`) or a local filesystem path response suitable for download in the existing local app.
- Archive MUST include:
  - manifest;
  - structured visual intent snapshots;
  - exact compiled prompts;
  - ordered reference manifests;
  - actually used reference images;
  - generated raw/matted outputs;
  - shared scene background;
  - hashes/ids;
  - prompt compiler / app / spec version identifiers when available.
- Archive MUST exclude:
  - API tokens, `.env`, Authorization headers;
  - provider URLs containing secrets;
  - unrelated storyboard results/versions;
  - automatic network upload behavior.

## Provenance

- Every provider request creates an immutable `generation_record`.
- Component generation rows link to that record.
- Routine logs use allowlisted safe fields only and never print prompts, dialogue, image bytes, credentials, or full provider bodies.

## Failure kinds (minimum)

Reuse/extend safe kinds already used by visual endpoints:

- `configuration`, `invalid-request`, `invalid-image`, `unsupported-image-format`
- `anchor-required`, `style-required` (only if style authority missing when required by policy)
- `provider`, `timeout`, `invalid-output`
- `matte-failed` (no usable alpha / keyed backing failure)
- `database`, `conflict` / stale-operation equivalents
- `not-found`

UI maps these to concise Russian actionable copy.

## Logging events (safe fields only)

Add/extend events such as:

- `visual-hybrid-frame-start`
- `visual-background-start` / `visual-background-provider` / `visual-background-storage`
- `visual-character-state-start` / `visual-character-state-provider` / `visual-character-state-matte` / `visual-character-state-storage`
- `visual-hybrid-frame-outcome`
- `visual-diagnostics-export`
- existing placement / load-failed events

Allowed fields remain the feature-005 allowlist plus component type, scene key hash/id, matte outcome flags, generation record id, and app git commit when available.

## Non-goals in this contract

- Batch generate-all-frames
- Background approval gate
- Multi-scene manager
- Automatic full-panel fallback
- Interpret/Stage/source/dialogue/structural-edit contract changes
